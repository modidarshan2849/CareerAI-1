## Defects found and fixed this session

**Confirmed defect:** `absoluteMinimumSalary > targetSalary` was accepted with no validation
in both `components/PreferencesForm.tsx` and `app/api/preferences/route.ts`.

- **Root cause:** no validation function existed for this constraint anywhere in the codebase.
- **Fix:** added `validateSalaryPreferences()` to `lib/validation.ts` — a single implementation
  called from both the client form (instant feedback) and the API route (authoritative,
  returns HTTP 400 with a clear message on violation).
- **Regression test:** 5 new assertions in `lib/__tests__/validation.test.ts`.
- **Full suite rerun:** 227/227 pass after the fix.

No other defects were found in this session. One documentation self-correction: an earlier
draft comment in `scripts/seed-candidate-a.ts` incorrectly claimed Candidate A would trigger
a forced domain-confirmation prompt. Actual behavior (verified by direct execution) is that
Candidate A's most recent role classifies confidently, so no forced prompt appears — only the
always-visible "Change direction" control does. The comment was corrected and a test
(`candidateAFixture.test.ts`) now enforces this claim going forward.
